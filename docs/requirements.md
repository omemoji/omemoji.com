# 機能要件

omemoji.com が満たすべき機能を、実現手段から切り離して記述したもの。
Hono（SSG）への移植後もこれらを満たすことがゴールになる。

- 現行の Astro 実装がこれをどう実現しているかは [`current-implementation.md`](./current-implementation.md) を参照

## 1. サイト全体

- 個人ポートフォリオサイト。日本語（`lang="ja"`）。
- 公開 URL は `https://omemoji.com/`。
- 全ページを事前生成した静的サイトとして配信する。実行時のサーバ処理を必要としない。
- URL は末尾スラッシュを持たない（`/articles/2` であって `/articles/2/` ではない）。
- ページビューを計測する。計測スクリプトは初期表示をブロックせず、遅延して読み込む。

## 2. ページ構成

| パス | 内容 |
| --- | --- |
| `/` | About。自己紹介・アカウント・実績を記事と同じ記法で記述する |
| `/articles` `/articles/2` … | 記事一覧（ページネーションあり） |
| `/articles/<slug>` | 記事詳細 |
| `/articles/tag/<tag>` `/articles/tag/<tag>/2` … | タグ別記事一覧（ページネーションあり） |
| `/artworks` `/artworks/2` … | 作品一覧（ページネーションあり） |
| `/artworks/<id>` | 作品詳細 |
| `/artworks/tag/<tag>` … | タグ別作品一覧（ページネーションあり） |
| `/404` | Not Found ページ |
| サイトマップ | 検索エンジン向けの XML サイトマップ |
| OGP 画像 | 記事・作品それぞれの個別 OGP 画像（後述） |

記事の slug はディレクトリ階層を含む（例: `2025/03/golden_kamuy/golden_kamuy`）。

## 3. コンテンツモデル

### 記事

各記事は以下の情報を持つ。すべて必須。

| 項目 | 型 | 用途 |
| --- | --- | --- |
| `emoji` | string | 一覧・詳細のアイキャッチ |
| `title` | string | タイトル |
| `description` | string | 概要。meta description と OGP に使う |
| `date` | Date | 公開日。ソートキー |
| `tags` | string[] | タグ |
| `published` | boolean | 公開フラグ |

- 本文は Markdown で記述する。
- 記事に紐づく画像は記事本文と同じ場所に置き、相対パスで参照できる。
- **`published: false` の記事は本番では公開しない。開発環境では下書きとして表示する。**

### About

- 記事と同じ記法で本文のみを持つ。追加のメタ情報は不要。

### 作品

各作品は以下の情報を持つ。

| 項目 | 必須 | 用途 |
| --- | --- | --- |
| `id` | ○ | URL の識別子 |
| `src` | ○ | 画像 |
| `title` | ○ | タイトル |
| `tag` | ○ | タグ（複数） |
| `href` | – | 外部リンク（応募先・掲載元など） |
| `description` | – | 説明文 |

- 一覧・詳細ともに**新しい作品が先に並ぶ**。

## 4. 一覧とページネーション

- 記事一覧は 1 ページあたり **7 件**、公開日の降順。
- 作品一覧は 1 ページあたり **9 件**、新しい順。
- ページ送りは全ページ番号へのリンクを列挙する（「次へ」だけの形式ではない）。
- タグ別一覧も同じページネーション仕様に従う。
- タグはクリックでそのタグの一覧へ遷移できる。

## 5. 記事の表示機能

### 記法

本文で以下が使えること。

- 絵文字ショートコード（`:smile:` 形式）
- ルビ
- 数式
- 脚注（脚注セクションの見出しは「脚注」）
- 生の HTML
- コードブロックのシンタックスハイライト

### コードブロック

- ライト / ダークの両テーマに対応する。
- 行番号は既定で非表示、記事ごとに有効化できる。
- 長いコードは既定で折りたたみ、展開できる。
- **Caddyfile のシンタックスハイライトに対応する。**

### 見出しと目次

- 見出しにはアンカー ID が付き、見出し自体がそのアンカーへのリンクになる。
- 見出しがある記事には目次を表示する。**見出しが 1 つも無い記事には目次を表示しない。**
- 目次に載せるのは深さ 3 までの見出し。深さに応じてインデントする。
- 目次は折りたたみ・展開できる。

### リンクカード

- **段落中にリンクが 1 つだけ置かれ、それが裸の外部リンクである場合**、通常のリンクではなくカード表示にする。
- カードにはリンク先のタイトル・説明・サムネイル画像を表示する。
- リンク先が SPA などでメタ情報を返しにくい場合でも、可能な限りタイトルと画像を取得する。
- サブドメインのページで画像が取得できない場合は、親ドメインの画像で代替する。
- メタ情報が全く取得できなくてもビルドは成功し、そのリンクは表示され続ける。
- サムネイル画像は配信サイズに縮小したうえで自サイトから配信する（外部への直リンクにしない）。

### 記事詳細のその他

- 記事の絵文字・タイトル・タグ・公開日をヘッダに表示する。
- 記事末尾に一覧へ戻る導線と、SNS 共有ボタンを置く。

## 6. 作品の表示機能

- 作品詳細では画像を大きく表示し、クリックで原寸画像を開ける。
- タイトル・タグ・説明文を表示する。
- 同じ作品群を横スクロールで一覧でき、現在の作品が分かる（Pixiv のような選択欄）。
- 作品末尾に一覧へ戻る導線と、SNS 共有ボタンを置く。

## 7. 画像

- 本文画像・作品画像は次世代フォーマットに変換して配信する。
- 表示幅は本文幅（700px）を基準とし、**高さは 540px を上限**にアスペクト比を保って縮小する。
- 読み込み前からアスペクト比が確定し、レイアウトシフトが起きない。
- ファーストビューの画像は優先的に読み込む。
- 本文画像にはキャプション（alt テキスト）を表示する。**作品画像にはキャプションを表示しない。**
- 外部の HTTPS 画像も扱える。

## 8. OGP / メタ情報

### 全ページ共通

- `title` / `description` / favicon
- 著者・作成者・発行者の情報
- サイトマップへのリンク
- RSS フィードへのリンク
- OGP: タイトル・説明・URL・サイト名・画像
- Twitter Card: サイト / 作成者アカウント（`@omemoji_art`）・タイトル・説明

### OGP 画像

- **作品**の詳細ページに専用の OGP 画像を**ビルド時に生成**する（1200×630 PNG）。作品画像を余白付きで収める。
- **記事**の詳細ページにも専用の OGP 画像を**ビルド時に生成**する（1200×630 PNG）。タイトルとサイトのアイコンを載せ、日本語タイトルは文節単位で改行する。
  - **記事の画像は Twitter Card にしか出さない。**`og:image` を読む通常のリンクカードには、記事もサイト共通の画像（720×720）を出す。
- 個別画像を持たないページは、サイト共通の画像（720×720）にフォールバックする。
- 個別の画像を持つページ（記事・作品の詳細）は大きい画像付きカード（`summary_large_image`）、それ以外は通常カード（`summary`）で共有される。

## 9. サイトマップ

- 検索エンジンにインデックスさせたいページのみを含める。
- **一覧のページネーション（2 ページ目以降）とタグ別一覧は含めない。**

> 現行実装の除外条件は、記事・作品の詳細ページまで巻き込んで除外している疑いがある。移植時に意図を確認し、上記のルールに沿って宣言的に書き直す。

## 10. 定数

| 値 | 用途 |
| --- | --- |
| 700 | 本文幅（px） |
| 7 | 記事一覧の 1 ページあたり件数 |
| 9 | 作品一覧の 1 ページあたり件数 |
| `omemoji.com` | ホスト名 |
